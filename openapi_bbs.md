# 1. Назначение

OpenAPI описывает REST-интерфейс Banking Billing System для расчёта комиссии и завершения биллинговой операции.

# 2. Методы API

| Метод | Endpoint | Назначение |
|---|---|---|
| `POST` | `/api/v1/billing-operations` | Рассчитать комиссию и получить решение о возможности продолжения операции |
| `GET` | `/api/v1/billing-operations/{operationId}` | Получить текущее состояние операции |
| `PATCH` | `/api/v1/billing-operations/{operationId}` | Передать результат денежной операции и завершить биллинг |

# 3. Коды ответов

| Код | Описание |
|---:|---|
| `200` | Запрос успешно обработан |
| `400` | Некорректные данные запроса |
| `404` | Биллинговая операция не найдена |
| `409` | Конфликт при повторном использовании `Idempotency-Key` |
| `412` | Значение `If-Match` не соответствует текущему `ETag` |
| `422` | Запрос не может быть обработан по бизнес-правилам |
| `423` | Ресурс заблокирован для изменения |
| `428` | Не передан обязательный заголовок `If-Match` |
| `429` | Превышен допустимый лимит запросов |
| `500` | Внутренняя ошибка Banking Billing System |
| `503` | Сервис временно недоступен |
| `504` | Не получен ответ зависимого сервиса в установленное время |

# 4. Описание значимости артефакта

| Раздел | Содержание |
|---|---|
| Процесс и контекст использования | OpenAPI-спецификация используется при проектировании интеграции системы денежных переводов с Banking Billing System. Артефакт описывает REST-интерфейс, через который выполняется расчёт комиссии, получение состояния биллинговой операции и передача результата денежного перевода. |
| Цель создания | Зафиксировать единый контракт взаимодействия между системами: доступные методы, URI, параметры, структуры запросов и ответов и коды ответов. |
| Что становится определено | Определяются методы `POST`, `GET` и `PATCH`, обязательные параметры и заголовки, структуры JSON-запросов и ответов, правила валидации данных, HATEOAS-ссылки и возможные HTTP-коды. |
| Пользователи артефакта | Системный аналитик использует спецификацию для согласования контракта интеграции. Backend-разработчики — для реализации API. Тестировщики — для проверки запросов, ответов и ошибок. |
| Использование в дальнейшем | Спецификация используется при реализации REST API, подготовке контрактных и интеграционных тестов, а также может использоваться для формирования документации по API. |
| Последствия отсутствия | Без спецификации взаимодействующие системы могут по-разному трактовать состав и формат данных, обязательные параметры и коды ответов. Это может привести к ошибкам интеграции и дополнительным доработкам. |
