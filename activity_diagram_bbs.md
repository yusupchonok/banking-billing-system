# 1. Назначение

Activity Diagram показывает обработку комиссии в рамках денежной операции.

Система денежных переводов до выполнения перевода обращается в Banking Billing System. Billing рассчитывает комиссию, проверяет возможность её списания и возвращает решение. После выполнения перевода система денежных переводов передаёт его итоговый статус для завершения биллинговой операции.

# 2. Основные шаги

| № | Шаг | Результат |
|---:|---|---|
| 1 | Система переводов вызывает `POST /api/v1/billing-operations` | В Billing переданы данные операции |
| 2 | Billing проверяет входные данные и `Idempotency-Key` | Исключены некорректные и повторные запросы |
| 3 | Billing получает тариф и клиентские условия | Получены данные для расчёта |
| 4 | Billing рассчитывает комиссию | Определена сумма комиссии |
| 5 | Billing сохраняет начисление | Расчёт зафиксирован |
| 6 | Billing обращается в АБС для проверки возможности списания комиссии | Получено решение по счёту |
| 7 | Billing возвращает `APPROVED` или `REJECTED` | Система переводов понимает, можно ли продолжать операцию |
| 8 | При `APPROVED` выполняется денежный перевод | Получен результат перевода |
| 9 | Система переводов вызывает `PATCH /api/v1/billing-operations/{operationId}` | Результат перевода передан в Billing |
| 10 | Billing списывает комиссию при успешном переводе или отменяет её при ошибке | Биллинговая операция завершена |

# 3. Основные ошибки

| Ситуация | Результат |
|---|---|
| Некорректные данные | `400 Bad Request` |
| Повторный запрос с другим телом и тем же `Idempotency-Key` | `409 Conflict` |
| Тариф не найден | `422 Unprocessable Content` |
| Недостаточно средств | `billingDecision = REJECTED` |
| Счёт заблокирован или закрыт | `billingDecision = REJECTED` |
| Внешний сервис недоступен | Повтор до трёх раз, затем техническая ошибка |
| Устаревший `ETag` при PATCH | `412 Precondition Failed` |
| Ресурс уже завершён | `423 Locked` |

# 4. Описание значимости артефакта

| Раздел | Содержание |
|---|---|
| Процесс и контекст использования | Артефакт используется при проектировании процесса расчёта и списания комиссии для денежной операции. Activity Diagram описывает взаимодействие системы денежных переводов с Banking Billing System, сервисом тарифов, сервисом клиентских данных и АБС. Диаграмма применяется на этапе проработки функциональной логики и интеграций между системами. |
| Цель создания | Зафиксировать последовательность выполнения процесса от получения запроса на расчёт комиссии до завершения биллинговой операции. Показать основные проверки, альтернативные сценарии и обработку ошибок. |
| Что становится определено | Определяется порядок вызова систем, момент расчёта комиссии, проверка возможности её списания, действия при успешном и неуспешном переводе, используемые REST-методы, основные статусы и варианты обработки ошибок. |
| Пользователи артефакта | Системный аналитик использует диаграмму для согласования логики процесса. Разработчики используют её при реализации взаимодействий между системами. Тестировщики — при подготовке позитивных и негативных сценариев. |
| Использование в дальнейшем | Диаграмма используется как основа для подготовки OpenAPI-спецификации, Sequence Diagram, тест-кейсов и постановок задач на разработку. |
| Последствия отсутствия | Без артефакта участники команды могут по-разному понимать последовательность действий, момент расчёта и списания комиссии и обработку ошибок. Это может привести к расхождениям между требованиями, реализацией и тестированием. |
